# New API Custom Console 前端 PRD

版本：v0.1（方案评审稿）
目标目录：`web-custom/`
产品类型：AI API 网关与渠道运营控制台

## 1. 文档目的

本 PRD 用于在开发前确认新版控制台的产品结构、页面职责和视觉方向。当前阶段只定义体验和界面，不修改现有 `web/`，也不实现后端数据结构。

新版前端必须与上游前端隔离，后续实现放在 `web-custom/`，通过稳定 API 与后端通信。

## 2. 产品目标

### 2.1 核心目标

- 让管理员快速判断系统是否健康、哪里异常、哪个渠道产生费用。
- 让 Key 管理从“单个分组”升级为“按厂商配置路由策略”。
- 让渠道、模型、分组、倍率和日志之间形成可追踪关系。
- 支持高密度桌面操作，同时保证平板和手机可用。
- 保留深色和浅色模式，默认深色模式。

### 2.2 非目标

- 不在第一阶段重做登录、支付和所有系统设置。
- 不把后台做成营销型 Landing Page。
- 不通过前端绕过后端权限和数据校验。
- 不复制现有 `web/` 的组件实现作为长期依赖。

## 3. 用户角色

| 角色 | 主要任务 | 最关心的信息 |
| --- | --- | --- |
| 系统管理员 | 管理用户、渠道、分组和系统配置 | 全局健康度、权限、异常、成本 |
| 渠道运营 | 调整渠道、模型映射和路由顺序 | 成功率、延迟、余额、失败原因 |
| 账务运营 | 查看额度、倍率和消费记录 | 费用、Token、倍率、结算 |
| 普通用户 | 创建和使用自己的 API Key | Key 状态、额度、可用模型、调用日志 |

### 5.1 布局规则

- 桌面端：左侧导航 240px，可收缩到 72px；顶部工具栏 56px。
- 内容区最大宽度 1600px，使用 8px 间距体系。
- 页面标题、筛选栏和主操作固定在内容顶部，不使用大幅 Hero 区域。
- 详情使用右侧 Drawer；跨实体流程使用独立页面；危险操作使用 Dialog。
- 列表页优先使用表格，卡片只用于 KPI、健康度和明确的重复实体。
- 不在卡片内嵌套卡片，避免信息层级混乱。

## 6. 视觉设计系统

### 6.1 色彩

| 语义 | 深色值 | 用途 |
| --- | --- | --- |
| Background | `#0B0F14` | 页面背景 |
| Surface | `#121923` | 表格、面板、Drawer |
| Elevated | `#182230` | 弹层、悬浮区域 |
| Border | `#283442` | 分隔线和边界 |
| Foreground | `#F4F7FA` | 主文字 |
| Muted | `#AAB7C4` | 辅助文字 |
| Action | `#4DA3FF` | 主操作、链接、焦点 |
| Billing | `#F5B84B` | 费用、倍率、重要提醒 |
| Success | `#35C98B` | 已启用、健康、成功 |
| Warning | `#F5A524` | 降级、接近限制 |
| Danger | `#F06464` | 失败、禁用、删除 |

浅色模式使用同一套语义 Token 映射，不直接反转颜色。状态必须同时有文字或图标，不能只依赖颜色。

### 6.2 字体

- UI 字体优先使用项目已有的 Public Sans，避免增加不必要的字体依赖。
- Key、模型名、分组名、倍率、请求 ID 和数字使用系统等宽字体。
- 正文最小 14px，移动端输入控件不小于 16px。
- 数字使用 tabular figures，避免实时数据刷新造成列宽变化。

### 6.3 组件原则

- 图标使用现有 Hugeicons 图标库，保持同一笔画风格。
- 图标按钮必须有 tooltip、可访问名称和明确的 pressed/disabled 状态。
- 主操作按钮每个页面最多一个视觉 Primary。
- 圆角以 6px 为主，避免大面积圆角胶囊化。
- 动效使用 150～300ms 的 opacity/transform，支持 reduced motion。

## 7. 页面 PRD

## 7.1 总览 Dashboard

### 页面目的

让管理员在 10 秒内判断系统是否正常、费用是否异常、哪个渠道需要处理。

### 首屏结构

```text
总览                                  今日  | 本周 | 本月  刷新

请求数        Token 消耗       费用          错误率        渠道可用率
12,480        86.4M            $24.80        1.8%          97.4%

请求与 Token 趋势                         渠道健康度
折线图 + 时间粒度                         渠道 / 成功率 / 延迟 / 状态

模型消耗排行                              最近异常
模型 / 请求数 / Token / 费用               时间 / 模型 / 渠道 / 错误
```

### 关键状态

- 数据加载：使用骨架屏，不能显示空白面板。
- 无数据：说明当前时间范围没有请求，并提供“查看日志”和“创建 Key”入口。
- API 或数据失败：显示错误原因和重试按钮。
- 实时数据刷新：显示最近更新时间，不强制刷新用户当前筛选。

- 禁用厂商后，该厂商策略保留但不参与路由。
- 删除 Key 使用二次确认，并提供短时间撤销提示。
- 批量操作必须显示影响数量和操作结果。

## 7.5 流量与日志

### 默认视图

```text

```

### 日志详情

- 请求基本信息

- 费用计算信息

## 8. 关键用户流程

### 8.1 创建带多分组的 Key

```text
创建 Key
  → 填写名称和有效期
  → 选择 OpenAI 分组及优先级
  → 选择 Claude 分组及优先级
  → 关闭不需要的厂商
  → 配置额度和模型限制
  → 预览最终路由策略
  → 提交并显示一次性完整 Key
```

### 8.2 处理渠道异常

```text
总览发现错误率上升
  → 点击异常渠道
  → 查看最近错误和 P95 延迟
  → 查看受影响分组和 Key
  → 禁用渠道或调整分组顺序
  → 验证健康检查
  → 返回总览确认恢复
```

## 9. 权限和状态

所有页面都必须区分以下状态：

- 加载中
- 空数据
- 无权限
- 请求失败
- 部分数据失败
- 已禁用
- 已过期
- 额度不足
- 未保存变更

前端只负责展示和引导，最终权限、额度、Key、分组和计费校验由后端完成。

## 10. 响应式方案

| 宽度 | 布局 |
| --- | --- |
| ≥1440px | 完整侧栏、双栏/三栏数据面板、表格全部字段 |
| 1024～1439px | 收缩侧栏、减少次要字段、详情使用 Drawer |
| 768～1023px | 折叠侧栏、表格转为分组行、图表改为单栏 |
| <768px | 顶部导航 + 抽屉菜单、列表转为实体行、详情全屏 Drawer |

移动端优先展示：状态、名称、路由策略、额度和主要操作；次要字段进入详情。

## 11. 前端技术边界

```text
web-custom/
├── src/
│   ├── app/              # 路由、主题、权限、Query 配置
│   ├── components/       # 纯 UI 组件
│   ├── features/         # dashboard、keys、channels、logs...
│   ├── lib/api/          # 后端 API 适配层
│   ├── stores/            # 少量全局 UI 状态
│   ├── i18n/              # en/zh/zh-TW/fr/ru/ja/vi
│   └── styles/            # 设计 Token 和全局样式
└── README.md
```

- 使用 React 19、TypeScript、Rsbuild、TanStack Router、TanStack Query、Tailwind 和现有 Base UI 体系。
- API 请求统一经过适配层，页面不直接拼接请求细节。
- 新前端不导入 `web/src` 内部模块。
- 所有 UI 文案必须走 i18n。
- 大列表使用虚拟化，图表按路由懒加载。
- 每个核心流程补充交互测试和响应式回归测试。

## 12. 第一阶段验收标准

- 可以查看总览 KPI、趋势、渠道健康度和最近异常。
- 可以创建、编辑、禁用和删除 Key。
- 一个 Key 可以分别配置多个厂商的分组、启用状态和优先级。
- Key 详情可以看到完整路由策略预览。
- 列表支持搜索、筛选、分页和批量操作。
- 所有页面具备加载、空数据、错误、无权限和禁用状态。
- 375px、768px、1024px、1440px 四个尺寸下无横向溢出。
- 支持键盘操作、可见焦点、语义标签和 reduced motion。

## 13. 待确认决策

1. 默认主题是否确定为深色，浅色作为可选主题。
2. 一级导航是否采用“总览、日志、Keys、渠道、模型与分组、用户、设置”这一结构。
3. API Keys 是否将“厂商路由策略”作为新版最核心的差异化功能。
4. 首个可视化版本是否只实现总览和 API Keys，还是同时包含渠道管理。

确认后，下一步只在 `web-custom/` 创建前端壳和静态 UI 原型，不修改现有 `web/`。
